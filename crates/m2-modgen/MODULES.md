## Recommended porting order

### 1. Leaf modules, no C++ state - 37 functions

`dbg` (5), `time` (5), `math` (20), `pack` (2), `fly` (2), `profiler` (2), `eventMgr` (1)

Pure functions or one-line forwards. `dbg`/`time`/`math`/`pack` are already proven by the real-build test; they validate the generator in the Bevy host first.

### 2. Process and platform services - 196 functions

`app` (109), `systemSetting` (35), `snd` (14), `ime` (33), `ServerStateChecker` (5)

Each wraps one singleton (`CPythonApplication`, `CPythonSystem`, `CSoundManager`, IME, server pinger) that the Rust client replaces with Bevy resources. `app.Loop` is the entry point where Bevy takes over (rust_port.md, finding 1).

### 3. Window system - 253 functions

`wndMgr` (155), `grp` (54), `grpImage` (15), `grpText` (21), `grpThing` (8)

The UI tree and 2D drawing: required before any script can show a window. Handles are pointers passed as Python ints (`handle:*` types), so Rust must hand out stable ids. The largest callback surface (`PythonWindow` events into Python).

### 4. Network - 122 functions

`net` (122)

Needs the packet layer (Phase 4). 151 callback sites into the Python phase handlers; the module itself is mostly thin sends.

### 5. World and actors - 374 functions

`player` (130), `chr` (78), `chrmgr` (36), `background` (48), `item` (36), `skill` (40), `nonplayer` (6)

Depend on the game state ported in Phases 3-4. `player` is the biggest module (about 300 functions): port it in groups by owner (`CPythonPlayer` slots, skills, quick slots, party).

### 6. The rest - 197 functions

`quest` (5), `guild` (34), `shop` (18), `safebox` (12), `exchange` (18), `messenger` (5), `miniMap` (27), `textTail` (18), `effect` (7), `event` (23), `chat` (30)

Independent, mostly data-in/data-out; each can be a separate Rust module with its own trait.

Method per step: regenerate the shim for the module with the empty prefix (the generated `initX` replaces the hand-written one), implement the generated trait in Rust, run the unmodified scripts, and keep the API snapshot test green. Functions in the table above are ported by hand first and then described in the spec manually.
